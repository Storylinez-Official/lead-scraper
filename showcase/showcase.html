Product showcase

LeadScraper

Finds products that have documentation, audits how good that documentation is, finds who to talk to, and drafts the cold-email opener. Every decision is shown live.

36leads processed in recorded runs
17qualified with a full report
6pipeline steps, LangGraph
The brief

From a directory listing to a ready-to-send opener

  • Start from listing sites: GitHub topics (api, developer-tools) and Product Hunt developer tools. Sources live in config, not code.
  • Keep only products whose business needs documentation, and that actually have it.
  • Crawl the site for emails and phone numbers; AI cleans the list.
  • AI audits the docs for quality, completeness and usability.
  • Write a report: summary, prioritised improvements, outreach opener.
  • Deterministic flow: every lead either continues or stops with a recorded reason.

How it works

Six steps, each one decides whether a lead continues

STEP 2.1

Qualify

Header scan for doc words + AI: is this a business that needs docs?

Regex + AI
STEP 2.2

Find docs

Candidate pages scored by regex signals: code blocks, endpoints, curl, doc platforms.

Regex only
STEP 3

Crawl contacts

Same-site crawl, emails and phones from mailto/tel, text, JSON-LD.

Regex only
STEP 4

Purify

AI dedupes and drops invalid contacts; a guard blocks anything not crawled.

AI + guard
STEP 5

Audit docs

AI scores quality, completeness, usability 0-10 with justifications.

AI, structured
STEP 6

Report

Summary, prioritised improvements, outreach opener. Lead score by fixed rubric.

AI + rubric

Gate after 2.2: no docs, lead stops. Gate after 3: no email or phone, lead stops.

LangGraph state machine. After each node a conditional edge continues only while status is running; otherwise the lead ends as skipped or error with the step and reason saved. All LLM calls use temperature 0 and strict JSON-schema output (gpt-4.1-mini).

Lead score

Lead score is calculated in code, not by the AI

Documentation gap

docs <= 3: +25 | 4-5: +20 | 6: +10
7: 0 | 8: -15 | 9-10: -30

Who we can reach

named person: +10
team inbox or phone: +5
only security/legal inboxes: -15

Developer product

API, SDK, platform, CLI, library,
framework, open source: +10

Docs size

<= 2 pages sampled and <= 3 nav links:
-10 (very small docs site)

Start at 50, add each rule, clamp to 0-100.

In early runs the model gave every lead 70-75; with rules it applied them inconsistently and its arithmetic did not match its own explanation. The score now comes from fixed rules and the dossier shows the breakdown.

Output

Every run leaves files a sales team can use

  • leads.csv: one row per lead, status, where it stopped and why, docs URL, contacts, scores, outreach subject.
  • leads.jsonl: same rows, appended as each lead finishes, so a crash loses nothing.
  • leads/<domain>.json: full pipeline state with the evidence behind every decision.
  • reports/<domain>.md: readable report for each qualified lead.
  • summary.json: counts by status and by the step where leads stopped.
  • CLI: python -m leadscraper run | lead <url> | collect | graph | serve
